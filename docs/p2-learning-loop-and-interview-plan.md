### 1.1 マイグレーション 0016：`content_items`

PRD の「発布台帳」12 項目を**列として持つ**。P0-14 の受入条件（来源・版権状態・能力点・教研審査状態）はこの表で満たす。

```
content_items(
  id, item_kind,                         -- word_order | article | katakana | pronunciation | mcq
  exam_level, knowledge_point_ref, skill_ref,
  payload jsonb,                         -- 題型ごとの本体
  -- 発布台帳（PRD §3.4）
  dataset_version, content_version,
  source_name, source_url,
  license_name, license_scope, commercial_allowed boolean,
  attribution_text, attribution_location,
  author, reviewer, reviewed_at, evidence_link,
  status,                                -- draft | in_review | published | retired
  created_at, updated_at
)
```

- `status='published'` への遷移をトリガーで塞ぐ：台帳 12 列のいずれかが NULL なら拒否（PRD「欠けたら発布不可」）。
- `commercial_allowed=false` の行は published に遷移できない。
- 日本語解説は**日本語母語の教研レビュー必須**。`reviewer` は非母語翻訳稿を承認できない運用とし、レビュー体制は §5 の未決事項。
- 署名（attribution）は画面上に実在させる：クレジット面を 1 つ用意し `attribution_location` から参照する。

## 2. 毎日ループ・生命値・FSRS（P0-08 / P0-10 / P0-11）

### 2.1 前提となる制約（調査済み）

- `knowledge_evidence`（0009）は `attempt_id` / `answer_id` NOT NULL ＋トリガーで
  「提出済み formal attempt」を要求する。**毎日復習はここに書けない。**別表を立てる。
- `enforce_student_knowledge_write`（0010／0012 で強化）は `mastery_score` / `state` / `due_at` が
  `calculate_student_knowledge_*()` の戻り値と**完全一致**であることを要求する。
- `migrate.ts:48` が適用済みマイグレーションをチェックサム検証するため、**0010 / 0012 は編集不可**。

### 2.2 マイグレーション 0017

```
daily_sessions(id, student_id, session_date, status, target_count, completed_count, ...)
  UNIQUE(student_id, session_date)                 -- 1 日 1 セッション
daily_answers(id, session_id, content_item_id, outcome, ...)  -- 追記専用
student_lives(student_id PK, lives, updated_at)               -- 投影
life_ledger(id, student_id, delta, reason, source_ref, ...)   -- 追記専用
  UNIQUE(student_id, reason, source_ref)           -- P0-10「二重減算しない」を一意キーで保証
```

生命値は `game_reward_ledger`（0015）と同じ「追記台帳＋投影」パターンを**再利用**する。新方式を発明しない。

- 上限 5／誤答 −1／30 分で +1／0 で継続制限。回復は読み取り時に経過時間から算出（cron 不要）。
- **課金回復は [TBD]**（PRD で商店ルール未確定）。実装しない。

### 2.3 FSRS は 2 分割する

テスト計画 P0-11 が実際に検証するのは**上限だけ**（新 ≤20 / 老 ≤60、復習を通常関卡に混ぜる）。

- **P0-11a（今回）**：上限と混在。既存の 1/3/14 日バンドの上に載る。スケジューリング変更なし。
- **P0-11b（別途）**：真の FSRS。`stability` / `difficulty` 列が必要で、失敗時に stability は**下がる**。
  現行トリガーの等値検査と正面衝突するため、新 `calculate_*` 関数を足して等値検査を新関数側へ移す
  マイグレーションになる。アーキ契約 §2.1 に `stability_days` の設計はあるが 0010 で出荷されていない。
  **「FSRS というアルゴリズム」なのか「上限＋間隔反復」なのかを先に決める**（§5）。

### 2.4 関卡

1 日 19 問、英検 3 級の能力点を明示。誤答フィードバックは正誤だけでなく
**「日本語の思考順序と英語構造の差」**を説明する（P0-09）。

## 3. 日本人特化 4 題型（P0-12〜15）

毎日関卡の中の**出題種別**なので、§1 と §2 の完了が前提。

| 題型 | 実装要点 | 受入 |
| --- | --- | --- |
| 語順ブロック | 語ブロックのドラッグ＋**キーボード操作**の両対応 | 唯一解、または規則定義された等価解を通す |
| 冠詞センサー | a / an / the / 無冠詞の時間制限選択 | **タイムアウトを知識誤りにしない**（別 outcome）。解説は具体的な冠詞規則を指す |
| 和製英語ハンター | 片仮名語が自然な英語かを判定 | 出題ごとに来源と教研審査状態（§1.1 で担保） |
| 母音切除 | 目標音節との比較、母音挿入位置の提示 | 判定不能時は「採点できません、もう一度」。**擬似的な精密スコアを出さない** |

**母音切除は音声ベンダー決定が前提**（§5）。他の 3 つは音声不要なので先行できる。

## 4. AI 二次試験模擬（P0-16〜21）

6 段階：入室と挨拶 → 音読 → 文章問答 → イラスト問答 → 個人質問 → 結果報告。
評価は 4 次元（内容／文法・語彙／発音／コミュニケーション）。報告は得点レンジ＋根拠文＋改善提案 3 件以内＋保護者要約。

重い状態機械が 2 つある：

- **P0-18 中断復帰**：完了段階を保持し、現在段階から再開。再提出・再採点・再計時をしない（既存の冪等パターンを踏襲）。
- **P0-19 / P0-20 マイク不可**：固定問題のタイピングに切替え、結果に「非完全模擬」を明示。録音中の権限剥奪は
  安全終了し、欠損音声を上げない。
- **P0-21 低信頼**：「再録音が必要」を表示し、当該回はトレンドに入れない。

> **上線阻断（PRD）**：音声処理地・ベンダー・保存期間・削除機構・未成年同意文が法務確認されるまで、
> AI 口語は公開テストに出せない。企画書 v2.0 は音声データの海外第三者処理を APPI レッドラインとしている。

      ↓
